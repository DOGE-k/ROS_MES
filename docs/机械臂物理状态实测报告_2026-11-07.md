# 机械臂真机物理状态实测报告

> 测量时间：2026-11-07（下位机重新上电后）
> 总线：ZLG USBCAN-II / CAN 2.0B / 500 kbps / 29 位扩展帧
> 适配器设备节点：`/dev/bus/usb/002/005`
> 测量方式：被动监听 + 模块状态查询 + 三轴各一次最小幅度相对运动，未发送回零、未发送急停

## 2 测量过程与原始证据

### 2.1 上电后未绑定态（被动监听 4s）

```text
UID 宣告帧数 = 8（约 2Hz）
ID   = 0x15BC00A4
DATA = 01 52 50 06 00 20 00 49
（byte0=设备类型 0x01；byte1..7=UID 低 56 位）

状态查询应答：
ID   = 0x003C2060
DATA = 01 ff 00 07 00 00 c3 c3
proto=1  SEG=0xFF(未绑定)  ARM=0  AxisBase=0  exist=0x07  ready=0x00  state=0x00
```

判定：模块处于**上电未绑定**状态，只有 UID 宣告，未就绪、不允许运动。

### 2.2 绑定 SEG=0 / ARM=1

```text
下行：ID=0x15BC0020  DATA=52 50 06 00 20 00 49 00

组号确认：ID=0x15BC0050  DATA=52 50 06 00 20 00 49 00   -> SEG=0, Result=0
臂位确认：ID=0x15BC0060  DATA=52 50 06 00 20 00 49 11   -> ARM=1, AxisBase=1
```

### 2.3 绑定后状态复核

```text
ID   = 0x00002060
DATA = 01 00 11 07 07 03 c3 c3
proto=1  SEG=0  ARM=1  AxisBase=1  exist=0x07  ready=0x07  state=0x03
```

判定：绑定成功，电机1~3 存在且就绪，模块状态 `0x03` = 已绑定 + 允许运动。

## 3 状态判定说明

### 3.1 轴3（伸缩轴）

- 物理位置：约 2cm，接近顶部（用户现场确认）。
- 编码器为增量式基准，断电后基准丢失；固件未配置回零，无法通过软件重建基准。
- 上电后固件把当前位置当作 0：
  - 反向（收回）指令在 0 附近被 `Result=3`（参数越界）拒绝；
  - 正向（伸出）指令被接受，`+0.1mm` 到位 `0.10mm`，`+0.5mm` 继续到位。
- 连续正向步进到 `1.06mm` 时电机顶住机械上限，位置不再变化，固件持续返回 `Result=1`（忙）。
  发送单轴停止 `0x0440230C DATA=00` 后忙锁解除，随后 `-0.1mm` 被接受，位置退回 `0.98mm`。
- **结论**：本次上电基准下轴3 可用行程仅约 `0~1.06mm`，对应物理 `2.0~2.1cm`。
  0~30mm 全量程无法在当前基准下测出；若需全量程，只能在**已知位置（如完全收回到底部）重新上电**建立基准后再测，固件本身不支持软件回零。

### 3.2 轴2（摆动轴）

- `Result=0` 接受，产生正常到位事件与停止事件，驱动与编码器链路正常。
- 实测相对上电基准的可用区间：`-1.52° ~ +4.56°`。
- 连续 `+1°` 步进到 `4.56°` 后位移自然递减到 0，未出现 limit/fault 事件，判定为上行可用极限（历史记录的 2.65° 与本次不一致）。
- 单步 `1°` 指令的实际位移在 `0.05°~0.95°` 之间波动，响应非线性，属于待嵌入式确认的问题。
- 运动过程中会出现"有应答但不动"的假忙锁，单轴停止帧可清除（见 3.6）。

### 3.3 轴1（旋转轴）

- 未清忙时曾出现 `CmdAck result=0` 但到位 `0.00°` 完全无位移；**这不是硬件故障**。
- 发送单轴停止清忙后，轴1 恢复动作：正向 3 步累计 `+1.62°`（0.71°→3.11°），反向 3 步累计 `-1.42°`。
- 未触及任何限位或故障事件，实测工作区间 `+0.71° ~ +3.11°`（相对上电基准）。
- 既有"轴1 硬件故障"的结论应撤回，改为"固件假忙锁导致的间歇性无响应"。

### 3.4 位置反馈为 0 的含义

三轴位置反馈帧（`0x0480xx40`，int32，单位 0.01°/0.01mm）本次均只收到 1 帧且值为 0。结合"断电后基准丢失 + 固件不支持回零"，该 0 值**不代表物理零点**，只代表当前绝对基准未建立。不能据此判断机械臂在物理零位。

### 3.5 反馈时序

- 静止时下位机不上报位置，仅在上电后广播 UID 宣告。
- 位置/到位/停止帧只在收到运动命令后出现，采完即停。
- 未观察到心跳帧（固件未实现心跳）。

### 3.6 固件"假忙锁"（重要）

实测存在一种状态：连续下发若干运动帧后，后续命令仍返回 `CmdAck result=0`，但电机完全不动、无到位事件；此时其他轴的命令也会被 `Result=1` 拒绝。

- 典型表现：轴3 在机械上限处顶住后，忙锁持续超过 1 分钟不解除；轴2、轴1 随后也全部 `Result=1`。
- 解除方法：对目标轴发送**单轴停止帧**（`PRI=1 GRP=1 MSG=3`，DATA=`00`，例如轴1 `0x0440210C`、轴2 `0x0440220C`、轴3 `0x0440230C`）。
- 清除后所有轴恢复正常动作，且不会锁死系统。
- 因此，"有应答但不动"或"某轴硬件故障"的结论必须先排除假忙锁。

## 4 对其他 AI/后续操作的约束

1. **绑定只存 RAM**：断电/重启后必须重新执行"接收 UID 宣告 → 发送 0x15BC0020 绑定 → 校验 0x15BC0050/0x15BC0060"流程，否则运动帧返回 Result=2。
2. **轴3 已到机械上限**：实测 `1.06mm`（物理约 2.1cm）处顶住，**禁止再发正向（伸出）指令**。
3. **轴3 当前不能靠 CAN 回零**：固件未配置回零，`CAN_HOME_SUPPORTED` 相关回零帧无效；本上电基准下可用行程仅约 `0.08~1.06mm`，到物理底部还差约 2cm，需断电后手动收到最底再上电才能重建基准。
4. **假忙锁是固件行为，不是硬件故障**：`result=0` 但无位移、或连续 `result=1` 时，先发单轴停止帧（MSG=3, DATA=00）再重试，不要判硬件损坏。
5. **禁止发送全局急停** `0x00000000`：会锁存且软件无法解除，只能重新上电。
6. **指令间隔**：建议轴间间隔 ≥3s，并等待到位事件后再发下一条；长时间连续步进后主动插一次单轴停止清理忙状态。
7. 绑定成功后 UID 宣告停止；若再次看到 UID 宣告，说明模块已重新上电（处于未绑定态）。

## 5 复现命令速查

```text
绑定：       ID=0x15BC0020  DATA=UID56(7字节) + ((SEG<<3)|(ARM-1))
状态查询：   ID=0x00000020  DATA=Token(uint32 大端)
状态应答：   ID=0x00002060 + (SEG<<18)
运动：       ID=0x04402104 + (SEG<<18) + ((AXIS-1)<<8)  DATA=int16 增量 + uint16 速度（大端）
CmdAck：     ID=0x04802154 + (SEG<<18) + ((AXIS-1)<<8)  DATA=[ack_msg,result,detail]
位置反馈：   ID=0x04802140 + (SEG<<18) + ((AXIS-1)<<8)  DATA=int32 位置
到位事件：   ID=0x08C02180 + (SEG<<18) + ((AXIS-1)<<8)  DATA=[int32 angle,int16 err,status_bits,flags]
停止事件：   ID=0x08C02184 + (SEG<<18) + ((AXIS-1)<<8)  DATA=[StopReason,output_level]
```

Result：`0=接受 1=忙 2=未绑定/基准无效 3=参数越界 4=故障锁存 5=急停锁存`
StopReason：`1=正常到位 2=急停 3=单轴停止命令 4=限位/超位`
