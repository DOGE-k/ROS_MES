# 前后端开发入口

本文件适用于 `mes_web/` 的前后端任务，不是整个 ROS_MES 团队的全局规则。先检查当前分支、未提交修改和本次任务范围，保留已有工作；文档只提供定位和约定，涉及行为时核查当前代码。

## 工作范围

- `ros_mes_front/` 是 Vue 前端；`ros_mes_hou/` 是 FastAPI 业务后端。后端 `app/ros/` 是本侧维护的 ROS 适配层，可以按任务修改。
- 执行前后端任务时，`../robot_control_backend/` 中的节点、消息、启动文件、硬件配置只读，不修改 ROS 或固件协议。发现不一致，先核查现有契约能否由本侧适配；需要 ROS/固件调整的，记录证据、缺口和负责人待确认事项。
- `../docs/` 的共享三轴契约、ROS/CAN 资料、跨系统测试报告和整仓 ZIP 不因前后端整理而迁移或重写。共享协议变化由相关模块协同处理。
- `../deploy/`、根数据库、`../sqlite_create.py` 是共享资源，按本次任务的明确范围处理；不要将 ROS 配置当作后端配置随意修改，不自动运行建库/种子脚本，不清理与任务无关的数据或服务。
- 上述范围只约束前后端任务，不限制 ROS 团队在其模块内开发。

## 文档维护

- 当前接口/流程写入接口字段文档；本侧对接状态、证据和缺口写入对接状态清单；每次改动及测试结果写入现有改动记录，新日期在上。
- 小功能优先更新已有章节，不再为同一流程重复创建设计、实现、验收三份说明。确有独立设计价值时才单独建文档，并由入口链接。
- 共享 ROS 消息、话题和编号契约引用根 `docs/`，不在本侧复制另一套协议。文档与代码不一致时记录差异，不能擅改共享协议来配合猜测。
- 清楚区分：接口已定义、仓库源码已实现、现场部署版本已核实、后端已接入、前端已使用、模拟验证、真机验证。未知写“待确认”，源码或模拟消息不能证明固件或真机已支持。
- 微调 HTTP 成功只表明发送路径完成；设备接受、实际运动、到位分别需要对应证据。没有回执不推断成功/失败，不自动重发增量运动指令。

## 启动与验证

从各子目录运行命令，避免 SQLite 相对路径指向错误位置。前端开发：在 `ros_mes_front/` 执行 `npm run dev`；后端：在 `ros_mes_hou/` 使用其可用虚拟环境运行 `python -m uvicorn app.main:app --reload --port 8000`。

- 前端相关回归：`npm run test:finetuning`、`npm run test:drawing`；类型及生产构建：`npm run build`。
- 后端：在 `ros_mes_hou/` 使用虚拟环境执行 `python -m unittest discover -s tests`。
- 检查 Markdown 引用、`git diff --check` 和实际改动路径；报告通过项、未测项及环境。不要用旧测试总数证明新增场景。
- 默认使用模拟消息、测试替身和隔离数据库验证控制改动，不自动操作真实设备。当前真实/模拟连接由个人中心调试设置及后端配置管理，历史 `VITE_DEBUG_NO_ROS` 不再绕过后端；模拟结果不能写成真实反馈或真机验证。

前后端任务建议以 `mes_web/` 为工作目录，或在任务开始时明确读取本入口。根 README 仍是全团队的中立导航。
