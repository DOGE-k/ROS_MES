# 设备告警事件前端可见化设计（axis_fault / limit_event / vacuum_loss_event / can_fault）

> 状态：设计已定，代码待实施
> 范围：`ros_mes_hou/app/ros/`（后端归一化与订阅）、`ros_mes_front/.../FineTuningPage.vue`（前端展示）
> 不涉及：ROS 端消息定义、固件行为、批次判定逻辑、自动急停/自动重发

## 1. 背景与问题

ROS 端已向 MES 发布四类设备异常事件。核查当前代码后确认：

| 事件 | 后端归一化 | 后端订阅 | 前端分支 | 用户可见 |
|---|---|---|---|---|
| `axis_fault`（轴故障） | 有 | 有 | **无** | 否 |
| `limit_event`（限位） | 有 | 有 | **无** | 否 |
| `vacuum_loss_event`（失压） | 有 | 有 | **无** | 否 |
| `can_fault`（CAN 故障） | **无** | **无** | **无** | 否 |

### 1.1 三类事件"消失"的确切位置

不是"没写分支所以被忽略"，而是在 `applyFeedback` 的过滤链里被提前 `return` 掉，连丢弃痕迹都没有：

```js
// FineTuningPage.vue:1044-1051（当前代码）
if (confirmedSeg.value === null) return;                    // 未确认臂 → 全丢
if (feedback.module_id_space && feedback.module_id_space !== 'seg') return;
if (finiteFeedbackNumber(feedback.module_id) !== confirmedSeg.value) return;
if (feedback.connection_revision !== undefined && ...) return;
observeDrawingFeedback(feedback);
if (!confirmedUnitIds.value.includes(Number(initConfig.unitId))) return;
```

关键矛盾：`vacuum_loss_event` 的 `device_id` 是 **21~25（臂级）**，`module_id` 按业务号或 SEG 归属，而 `confirmedSeg` 是当前确认臂的 CAN SEG。只要两者不等，失压事件在到达任何 `data_type` 分支之前就被丢弃。

`axis_fault` / `limit_event` 的 `module_id_space` 为 `seg`，能过第二道，但 `module_id !== confirmedSeg` 时同样被丢弃——即**只有当前臂的故障才可能显示，且仍需新分支**；其它臂的故障永远看不到。

`can_fault` 是全局 CAN 总线状态，没有 `module_id` 语义，走同一过滤链必然被丢。

### 1.2 后果

设备报故障时页面保持安静，操作员无法区分"设备正常"与"故障事件被前端吞掉"。批次侧虽已独立中止（`finetuning_batch.py:462-469`），但中止原因只在批次结果里以一句概括文字出现，缺少原始故障字段。

## 2. 目标与非目标

### 2.1 目标

1. 四类事件在微调页可见，带固件原始字段与可判读中文说明。
2. 持续发布的故障事件不刷屏（去重窗口）。
3. `can_fault` 恢复（`state=ok`）时横幅自动消失，无需手动关闭。
4. 事件可见化不改变任何批次判定、联锁状态或运动下发行为。

### 2.2 非目标（明确不做）

| 不做 | 理由 |
|---|---|
| 自动急停 / 自动重发指令 | 仓库约定：无回执不推断成功/失败，不自动重发增量运动指令 |
| 改变批次完成/中止判定 | 判定已在 `finetuning_batch.py` 独立实现；前端卡片只展示 |
| 解除已有联锁 | 联锁由后端 `batch_manager.set_safety` 管理 |
| 给 `axis_fault` 加"已恢复"状态 | 协议无恢复事件，只能留历史 |
| 新增独立告警页面 | 本次只在微调页扩展，避免页面数量膨胀 |
| 修改 ROS 端消息或固件 | 本侧只做消费；消息契约差异记录为待确认 |

## 3. 事件契约

### 3.1 已有三类（后端已实现，不改）

来源：[normalizer.py:128-134](../ros_mes_hou/app/ros/normalizer.py#L128-L134)

| 话题 | 消息类型 | `data_type` | 关键字段 | `module_id_space` |
|---|---|---|---|---|
| `/hardware/axis_fault` | `AxisFault` | `axis_fault` | `device_id`、`fault_bits`、`local_action`、`detail`、`duration_ms` | `seg` |
| `/hardware/limit_event` | `LimitEvent` | `limit_event` | `device_id`、`limit_type`、`output_level` | `seg` |
| `/hardware/vacuum_loss` | `VacuumLoss` | `vacuum_loss_event` | `device_id`(21~25)、`pressure_raw`、`loss_threshold` | `seg` |

这三个分支要求 `device_id` 在 1~15（轴级）才命中；`vacuum_loss_event` 额外要求 `device_id` 在 21~25（臂级）。

### 3.2 新增 `can_fault`

`std_msgs/String`，`data` 字段内嵌 JSON。按需求表拟定的字段：

| 字段 | 类型 | 说明 | 缺失时行为 |
|---|---|---|---|
| `state` | string | `"ok"` / `"error"` | 缺失按 `error` 处理 |
| `message` | string | 人类可读说明 | 缺失用默认文案 |
| `detail` | string | 补充明细 | 缺失不显示 |
| `channel` | string/int | CAN 通道标识 | 缺失不显示 |
| `timestamp` | string/number | 发布侧时间 | 缺失不显示 |

`state=ok` 是恢复信号，前端据此清除横幅。

### 4.3 `normalizer.py`：加解析分支

`can_fault` 与其它事件不同构（`std_msgs/String` 套 JSON），必须单独解析，不能套 `event_fields` 那套数值字段提取：

```python
elif topic == topics["feedback_can_fault"]:
    data_type, feedback_type = "can_fault", "CAN 连接故障"
    module_id_space = "system"
```

并在函数末尾（`cmd_ack` 分支之后）补字段解析：

```python
if data_type == "can_fault":
    payload = msg.get("data")
    if isinstance(payload, str):
        try:
            payload = json.loads(payload)
        except (ValueError, TypeError):
            payload = {}
    payload = payload if isinstance(payload, dict) else {}
    normalized.update({
        "state": payload.get("state"),
        "message": payload.get("message"),
        "detail": payload.get("detail"),
        "channel": payload.get("channel"),
        "timestamp": payload.get("timestamp"),
    })
    normalized["valid_fields"] = [k for k in ("state", "message", "detail", "channel", "timestamp")
                                  if normalized.get(k) is not None]
```

注意：`module_id_space = "system"` 是新值，前端过滤链需识别并放行（见 5.2）。这个值不复用 `mixed`，避免和 `cmd_ack` 的"归属待确认"语义混淆。

## 5. 前端改动（`FineTuningPage.vue`，5 处）

### 5.1 扩展事件类型

```ts
// 474 行，现在只有 'info' | 'warning'
const deviceEvents = ref<Array<{ id: number; text: string; type: 'info' | 'warning' | 'error'; raw: string }>>([]);
```

`ackEvents` 保持不动（回执语义不需要 error 级）。

### 5.2 调整过滤顺序（**关键步骤**）

在 `applyFeedback` 里，把告警判断提到 seg/臂过滤**之前**，与 `cmd_ack` 同层：

```js
const applyFeedback = (feedback: any) => {
  if (feedback?.data_type === 'config_changed') { connectionChanged(); return; }
  if (!feedback || feedback.data_type === "error") { ...; return; }

  // 系统级 / 跨臂告警：不依赖当前确认臂上下文，必须在 seg 过滤前处理
  if (feedback.data_type === 'can_fault') { applyCanFault(feedback); return; }
  if (feedback.data_type === 'cmd_ack') { applyAck(feedback); return; }
  if (feedback.data_type === 'axis_fault' || feedback.data_type === 'limit_event'
      || feedback.data_type === 'vacuum_loss_event') {
    applyDeviceFault(feedback);
    return;
  }

  // 以下保持原顺序：遥测类才需要臂上下文
  if (confirmedSeg.value === null) return;
  ...
};
```

这一改动的实际影响：`axis_fault` / `limit_event` / `vacuum_loss_event` 从此**任何臂**都能显示，不再局限于当前确认臂。这是有意的——别的臂出故障，操作员同样需要知道。

### 5.3 新增状态与去重表

```ts
const canFault = ref<{ text: string; raw: string } | null>(null);
const deviceFaults = ref<Array<{ id: number; text: string; type: 'warning' | 'error'; raw: string }>>([]);
let deviceFaultSequence = 0;
const faultDedup = new Map<string, number>();
const FAULT_DEDUP_MS = { axis: 2000, limit: 2000, vacuum: 5000, can: 5000 };

const shouldRecord = (key: string, windowMs: number) => {
  const now = Date.now();
  if (now - (faultDedup.get(key) ?? 0) < windowMs) return false;
  faultDedup.set(key, now);
  return true;
};
```

去重 key 设计：

| 事件 | key | 窗口 | 说明 |
|---|---|---|---|
| `axis_fault` | `fault:{deviceId}:{faultBits}` | 2s | 不同故障位算不同事件 |
| `limit_event` | `limit:{deviceId}:{limitType}` | 2s | 软限位/机械限位分开 |
| `vacuum_loss_event` | `vacuum:{deviceId}` | 5s | 臂级，按臂去重 |
| `can_fault` | `can` | 5s | 只刷新横幅内容，不追加卡片 |

### 5.4 文案模板

严格按需求表：

```
轴 3 故障：fault_bits 0x1A（编码器异常）· 本地动作：停机 · 持续 320ms
轴 5 触发上行软限位 · 输出已保持
臂 2 吸盘失压：压力值 12 / 阈值 30
连接失败：CAN 连接失败，请检查 USB 端口或更换一个端口进行重试
```

`fault_bits` 位定义**只使用仓库已有依据**，不自行发明：

- [FineTuningPage.vue:995](../ros_mes_front/src/components/Main/ModulePage/FineTuningPage.vue#L995)：`(1<<5)|(1<<7)` 判故障
- [finetuning_batch.py:472](../ros_mes_hou/app/ros/finetuning_batch.py#L472)：`(1<<3)|(1<<4)|(1<<5)|(1<<7)` 判限位/故障/急停

已知位映射（仅这些，其余显示 `bit N`）：

| 位 | 含义 | 依据 |
|---|---|---|
| bit 3 | 限位 | batch 判据 |
| bit 4 | 急停 | batch 判据 |
| bit 5 | 故障 | batch + 前端判据 |
| bit 7 | 故障 | batch + 前端判据 |

未知位保留 `bit N` 形式并同时显示原始十六进制值，便于对固件手册。
